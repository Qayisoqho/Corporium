# 空索引全字段检索与启动进度

发布补记（2026-11-15）：本文所测源码及已通过的中英文大字号启动进度现纳入 **0.9.01115**。文内 0.9.01108 和“未重建”是测量完成时状态；本次冻结程序验证见[发布核验](RELEASE_0.9.01115.md)。

2026-11-15，Corporium 0.9.01108，仅源码；本轮未重建安装包。

## 结论与计时边界

全字段检索不再必须先组装整语言的词典正文和全部关联例证。没有已有全文投影时，先从 SQLite 来源列、类型化值与关联表筛选，再验证候选。已有全文投影的项目继续用原来的增量路径。

同轮空投影首次查询，十万句库 **32.88 → 1.67 秒**，密集库 **25.57 → 3.66 秒**。前轮十万句库记录为 26.77 秒；硬盘缓存及运行负载使本轮旧逻辑绝对时间不同。两种材料都明显改善，但**首次查询尚未达到一秒**，也不能把这些后台计时当作点击到界面稳定的计时。

此外，新版首次打开旧结构时要建立普通 SQLite 来源 B-tree 索引：密集库约 **3.34 秒**，十万句库约 **16.81 秒**，其索引页分别约 **84.6 / 268.7 MiB**。这项一次性升级成本另计，不能从首次使用成本里隐去。它不生成整库检索文档，后续写入由 SQLite 更新索引。启动进度会覆盖这一准备阶段；当前并未实现“旧项目升级加第一次查询也在一秒内”。

## 原来的时间花在哪里

同轮旧代码十万句库首次任务约 32.88 秒，其中词条索引准备 18.06 秒、关联例证字面值准备 10.15 秒、例证字面索引查询准备 1.16 秒；其余包括任务入口、提交和分页摘要。词条阶段中的文档刷新约 7.98 秒，属于前述 18.06 秒，不能重复相加。旧路径先读、解释整个范围，才知道查询需要哪些记录。

密集库词条准备约 5.35 秒、例证准备约 19.04 秒。它虽然句数少，但有大量继承标注和复杂词典结构。因此不能只看句数或把两库视为同一种负载。

新代码的补充分段探针中，十万句库约 2.01 秒：候选词典部分 0.52 秒、例证部分 1.43 秒，后者含来源不同值读取 0.61 秒。密集库约 4.23 秒：候选词典 0.55 秒、例证 3.61 秒，后者的不同值读取仅 0.11 秒，主要余量是大量已变化的继承词格。分段值来自额外一次带计数的探针，与表中首次样本存在运行波动；其中子步骤也不能重复累加。

## 实现与安全条件

- `dictionary_cold.py` 从词形、同形号和 `dictionary_value_rows` 的标量值找候选。词条义项的附加标注、变形表的继承、引用显示名、反向基本条目和媒体仍按原规则验证；不因快速筛选漏掉这些隐式命中。SQLite 的 ASCII 必要条件仅作保守排除，最终仍使用 NFC／大小写折叠规则。没有安全条件的查询使用完整 Unicode 判断。
- 正文直接读取 `sentence_text_rows` 的列，词格从 `sentence_word_rows` 筛选不同词形、标注及少量扩展。手工附加标注先筛选文本，再核对活跃层、单元及语言。通过现有关联表把命中的句子映回词条或语素。
- 已改变的继承词格继续使用原有解释器。密集库曾因逐次解释同样的标注及反复解析名称而再次变慢；现在相同研究输入复用结果。比较绑定修订是否相等、来源指纹、当前释义、覆盖模式等实际语义，不用每处不同的时间戳作为内容差异。复用不改变绑定或撤销记录。
- 当前查询结果在进程内有容量限制，SQLite 中最多保留八个冷查询的变动范围。普通释义修改只重查变动定义及引用；正文、手工标注、继承、外部 SQL 和撤销更新相应代次。随机事务代次避免回滚后的序号重用造成错误命中。进程没有候选值缓存时关闭扩展值队列，避免未使用这条查询路径的导入持续积累副本。
- 没有新增权威正文 JSON。现有开放扩展、媒体信息仍按旧格式读取；只有可能影响匹配的扩展需要解释，不能宣称完全没有 JSON。来源索引及候选值队列是可删除重建的派生数据，随便携 SQLite 备份清理。旧项目、交换格式、正文保存及撤销编码保持原意。

十万句库 `lemma8` 专项首次任务仅读取 111 个候选定义，未调用整句正文的批量头部组装。单条保存仍只读取一个媒体所有者、检查其两个附件；保存后的原查询及撤销查询只读一个变动定义。

## 启动进度窗口

`desktop_startup.py` 在导入服务端及 WebView 前创建原生 Windows 窗口，并提前取得单实例锁。重复启动会转到已有启动窗或主窗口，避免同时再开一个项目。

窗口显示运行环境、项目检查、安全快照、数据准备、本地服务、主窗口和页面／字体七个阶段，说明已完成及剩余阶段。数据准备还显示六个子步骤；SQLite 快照按已复制页数显示真实百分比。阶段数量不是剩余秒数，不制造估计倒计时。

主窗口先隐藏，页面确认数据恢复、首页内容和字体就绪后显示，启动窗同时关闭。启动失败关闭进度并保留错误反馈；偏好文件暂时无法写入也不能让主窗口一直隐藏。进度窗的关闭入口禁用，保留最小化，避免中断迁移；主窗口出现后使用原关闭流程。

双语文案跟随已保存的界面语言。字号角色从共用 CSS 读取，按上次界面比例显示；记住界面字体、粗细及斜体。品牌指定 Junicode，未注册的项目专用字体在原生阶段使用 Windows 回退，网页就绪后使用完整字体链。窗口不提供另一套字号设置。偏好监听只处理真正的字体／字号变量，不因普通工作区类名和几何变量变化重复测量布局。

源码原生冒烟中，未选项目时进度约 61 毫秒出现、页面交接约 2.21 秒；恢复既有 Tëlira 隔离项目时约 68 毫秒出现，七阶段、快照页数及六个数据子步骤均有实际记录。后者在同时运行回归时约 11.98 秒交接，作为功能核验，不能当作无干扰的启动速度对照。本轮未测新安装包的启动；冻结程序进入 Python 前的系统加载也无法由这段代码提前显示。

其他回归结束后的中文恢复复测：进度 107 毫秒出现，项目准备约 0.86 秒完成，WebView 页面加载事件在 5.44 秒，实际数据／字体就绪交接在 6.54 秒。记录为 `native-final-project.json`。这证明加载事件之后仍需等真正就绪；此次功能消除的是启动初期没有反馈的问题，不宣称整应用启动速度达到一秒。重复启动聚焦和释放句柄、完成后忽略迟到进度另有行为测试。
