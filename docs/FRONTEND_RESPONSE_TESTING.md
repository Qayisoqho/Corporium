## 就绪条件和旧口径纠正

从文档捕获click／input／change／keydown开始，等目标内容出现、fetch响应体读取／解析结束、前台任务及词典后台进度结束、字体就绪及DOM稳定，再跨动画帧。操作前等待前次刷新结束，百句翻页还核对首句ID实际改变。响应头与响应体结束分别保存为end与bodyEnd，最终记录含taskIdle=true和源码哈希。选择／输入使用自动化事件，页面初次加载另用导航时钟；不把自动化定位、前置滚动和展开菜单计入点击。

上一轮`build/frontend-response-audit-20261108`和本轮早期完整试跑只跟踪fetch响应头，部分就绪判断可能偏早。本轮将早期记录封存为`measurements-first-full.json`／`measurements-headers-only.json`，保留归因用途；最终报告的三列全部在修正后的统一口径下重跑，不能拿旧绝对耗时直接作最终恢复比值。历史文档保留当时数字并已标注范围。

早期响应体口径还会在任务轮询空隙中提前判为完成，尤其使旧版轨道时间偏短。相关中间记录保存在`measurements-pre-task-idle-partial.json`，不作最终基线；当前计时和操作前等待均检查任务状态，三版从干净副本重新完整测量。

修正口径后的首次完整复测还有4个输入情境未恢复，保留为`measurements-corrected-initial.json`／`summary-corrected-initial.json`。探针发现样式／布局已接近旧版，额外空闲等待来自词形表被句子输入误触发刷新；限定观察和输入范围、跳过相同表头隐藏值后，再从干净副本完整重测。固定输入宽度及额外缓存几何关系的探针无明显收益，未进入生产源码。

统计短任务还有400ms状态检查带来的完成窗口波动；最终改为40／80／160／320ms早期退让，再回到原400ms上限，后台词典保持80ms。取消、提交锁、进度和串行协议不变。修正后再次从相同输入恢复六份副本并完成下表全部三版五轮。

正式计时串行，逐轮轮换三版顺序，不与其他浏览器负载并行。Edge 156、1440×1000、Docoid、100%、无CPU节流。每轮新建上下文，未清空操作系统／后端缓存，不能称冷机启动。首次派生索引准备、原生安装版和后台长任务吞吐不在本轮范围。
