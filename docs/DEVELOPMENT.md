## 下划线按单一标注处理（2026-10-30，仅源码）

下划线`_`按同一词格内的空格替代字符保留，不作为语素或标签边界。`take_care_of`、`看_起来`在编辑时各占一格；`take_care_of.PST`仍由点号分隔基本标注与PST。已有文本和独立例句重新打开即使用同一规则，无需批量改写正文；连续、开头和末尾下划线在保存、撤销及导出中保留。

标签识别、候选、统计、自动特征、自动关联比较、单句补空、释义替换及带格式复制同步：不再从`look_PST`内部单独识别PST，也不把它当成`look.PST`匹配或跨下划线重排。若用户登记`NOM_SG`，整个名称是一项标签，不拆成NOM和SG。上下标两侧的下划线仍连接同一标注，旧上下标标签恢复不再从其内部推断另一标签。

变形表和模板的继承／附加标签允许含下划线的完整标注，如`take_care_of`继承后附加PST得到`take_care_of.PST`，不再报“复杂结构”。真正的语素边界和其他复杂结构保护照常检查；原始下划线不替换为空格。中英文共用。

`corpus.compact_gloss`不再清理下划线，`glossEditParts`不再据此创建编辑输入；格子来自原标注字符串，旧正文没有存储独立的下划线标签格，因此无需迁移。`grammar.tokens`在上下标保护后按真正分隔符识别完整原子，`grammar.mutate`允许完整下划线标签名称；`richGloss`与带格式复制保持同一识别范围，原始文字及上下标格式保留。

`lexicon.auto_gloss_key`、`sentence_dictionary.candidate`及`dictionary_gloss_sync.replace_short`移除下划线分隔语义，替换同时防止从上下标包装进入下划线原子的内部。`paradigms.addition/compose`和前端对应函数允许下划线；模板、普通义项附加标签和语素复用该规范。`script_tags.recover`只考虑完整标签候选。没有增加表、启动迁移或重写既有正文／身份。

## 英文同步核对、例句统一字号与保存后语素对齐

`--example-font-size:1.125rem` 提供统一的根字号，style.css、workbench.css、analysis-workspace.css中四行各自乘本语言比例；不从父例句的计算字号再乘。languageTypographyCSS仍为每个语言容器明确重置四组字体／变体／比例。旧版浏览器偏好仍是静态兼容回退，不依赖上一个语言。

`inlineWordLayout` 按真实语素边界计算 grid-column；自由释义内部的点号等列合并到相应词形输入的跨度，输入DOM、字段索引和编辑事件不变。真正边界不一致时保留原配对及既有核查提示。corpus.normalize_edited_pair 在成对空格清理后压缩标注，再按边界签名保守清理空词形；完整／Tab及两种原位保存载荷共用，随后按现有流程重新分析。

英文目录原已包含上一轮新功能译文；本轮静态审计9条关键短语，并实际打开英文完整／快捷编辑的附加标签及开关、分类帮助和排序把手，材料“北方”等保持原文。未重复翻译用户内容，也未新增未译作者文案。

例句的 IPA、语素、标注和翻译四行在 100% 时使用同一字号基准（全局100%时为18px），保留各语言单独设置的字体、变体和比例。阅读、原位编辑、首页和分析例句共用此基准；全局字号只叠加一次。没有发现把后一语言100%建立在前一语言比例上的累乘，已有语言比例不改写。

编辑时以 `-、=、+、~` 等语素边界对齐，点号、上下标和标签内结构仍可分别编辑，但归属于同一语素列。`opened-ne / 开.pst-sg` 中，opened 跨住“开.pst”的内部列，ne 与 sg 对齐。保存会清理空标注并重新检查边界；仅在删除空词形格后可恢复完全相同的边界序列时移除该空格，保留非空形式、零形式标注和真正不一致的分析，不猜切词形。撤销、原词格身份和逐词附加层保留。

仅源码更新，保留0.9.01026.4。

## 清空词格、释义附加标签、类排序与连续编辑

义项字段为 `short_gloss`／`gloss_addition`／`show_gloss_addition`，原生语素对应 `gloss`；缺省显示兼容旧数据。`sense_gloss.py`与`web/sense-gloss.js`负责组合，附加标签使用既有变形表的字面符号约定，变形表继承使用有效基本标注。`paradigms.project(..., ordinary=False)`供可写替换路径，普通义项保持原始文本；搜索投影组合原生／普通义项，并隐藏显示开关元数据。

category_classes新增position，旧库迁移前备份；语义类复用原position。class_changes只在提交的编辑器revision与操作前一致时返回本操作造成的更新，前端原位刷新选择框及必要基线，不重新打开词条；不覆盖独立并发编辑。形态类解绑用空class_id保留主要部分，交换跳过空类映射。新句保存通过corpusEntryCard替换自己的草稿，避免完整search刷新。

词条义项和语素的简短释义保持自由文本，附加标签单独保存，可从本语言已登记语法标签选择并用点号连接。每个义项的“显示附加标签”决定组合结果；取消勾选保留标签内容。完整／快捷编辑共用草稿，阅读、自动匹配和跟随标注采用组合结果，本句覆盖保留。查找替换的简短释义只修改自由文本，避免把组合显示写回原字段。

类列表行首把手可拖动排序，也支持 Alt＋上下键；只调整同级顺序，保存、重载、语言交换和撤销均保留。重命名同步更新引用，删除前说明对子类和绑定的处理。删除词类解除词类／子类绑定；形式类型删除后保持未指定；使用标签类型解除相应标签；语法标签分类删除保留标签定义和特征引用；形态类删除保留未分类的主要词形与备注；语义类沿用提升／删除子树选项。词条／语素编辑时管理分类保留草稿，独立窗口的并发修改仍受版本校验。

清空词格时，只剩 `-、=、+、~、<>、＝` 的空内容在保存时移除；真实词形、非空标注和转义字面符号保留，附加层／原身份可撤销恢复。文本新句在当前列表末尾原位编辑，仍追加到文本末尾；保存后保留卡片、当前页与筛选，下次检索按正常分页显示。

版本保持0.9.01026.4；此轮源码未重新打包。

## 目录

- 根目录 Python 模块：服务端、数据模型、导入导出与桌面外壳。
- `web/`：前端脚本、样式和页面；不需要 npm 构建步骤。
- `tests/`：后端与前端回归测试。
- `tools/`：合成数据库生成器及跨模块性能实验工具。
- `packaging/`：Windows 安装包配置、许可和虚构示例。
- `font/Junicode/`：附带许可的字体资源。

## 隔离验证

推荐通过根目录的 `run_tests.py` 运行测试。后端测试新建临时数据库，不接触现有用户项目；数据库访问被限制在此目录的 `build/` 内。不要将正式数据库放入测试目录。

源码自检可用 `python -B desktop.py --self-test build/desktop-check`，不会使用正常桌面配置。实际窗口验证应使用独立测试项目。

公开测试中的 Typst、无译文 Excel 和媒体输入均为合成材料；字体测试使用附带的 Junicode。它们覆盖相应格式与操作，不包含内部开发时使用的个人原始材料。

## 大规模材料

```powershell
python -B tools/test_materials.py generate --profile dense --sentences 10000 --output build/dense-10000/corpus.sqlite3
```

`smoke` 组合常用关联功能，`ordinary` 生成一般规模关联，`dense` 为每个适用词格建立词典关联，`research` 增加语法调查、时间轴和标签，`reduplication` 生成重叠形态。输出不得覆盖已有文件，并须位于 `build/` 内。

`tools/benchmark_modules.py --output build/performance --sizes 1000 10000` 可运行 Windows 下的跨模块实验。它会生成自己的数据库和短音频。单项耗时含服务端处理与序列化，不包含实际界面渲染；首次测量不清空操作系统文件缓存。需要实测后再报告性能，不能把内部旧材料上的数字直接用于此生成器。

`tools/migrate_paradigm_inheritance.py` 提供旧形态表释义的转换计划，并供相应回归测试使用。传入数据库路径时默认只预览；显式添加 `--apply` 才会备份并应用能精确还原原标注的转换。
