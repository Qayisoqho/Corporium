# 独立例句词典关联迁移

2026-11-12，Corporium 0.9.01108 源码

关联迁移早于正文删列。本文计时使用当时的数据库结构，当前正文来源见 [SQLite 正文与存储约定](SQLITE_STORAGE.md)。

## 存储与操作

- `independent_links` 是独立例句词典关联的来源。例句、目标条目、用法、义项、形式、词格位置和顺序都有独立列。词条反查和形式筛选使用索引。旧的导入、导出和读取响应仍可使用 `targets` 数组。
- `independent_dictionary_keys` 在词典定义写入时维护用法、义项、变体和变形义项的身份。关联保存和校验按这些身份查找。语法标签继续按所属语言检查。
- 逐词新增、改绑和解绑只解析涉及的词格快照。解除释义继承后，当时显示的标注按词格保存。关系、释义绑定、词格保留值和例句修订号一起提交。撤销和重做恢复同一组数据。只编辑例句中的关联时，编辑器单独提交关联字段。
- 正文的编辑、导出和显示仍读取所需正文。逐词关联使用单个词格的快照。分段和组分等附带快照保留各自的 JSON 编码。

## 迁移与核验

打开旧项目时，先通过 SQLite 备份完整数据库，再在事务内建立关系行、词格快照和词典身份目录。旧正文内的关联从正文列移除。只有关联发生变化的历史可转换为关系增量。含正文变化的旧历史保留原有恢复路径。旧构建读取迁移前的备份。

复用已有密集材料，包含 10,000 条文本句、1,000 条独立例句和 11,000 条独立关联。逐条比较了迁移前后的正文、修订号、关联顺序、标注及快照。复用十万句材料，包含 50,000 条文本句、50,000 条独立例句、50,000 条词条和 5,000 条语素。该副本原有独立关联数为零，写入对照在同一条既有例句上新增、改绑、解绑并撤销。两个副本的迁移内容对照、SQLite 完整性和外键检查均通过。

## 前后耗时

数字为 Windows 同机中位数，单位为毫秒。写入用应用后端处理函数执行，包含连接、校验、提交和撤销记录。密集库的写入各 5 次，十万句库各 3 次。筛选计数各 5 次，例证页和全库独立关联校验各 3 次。

| 操作 | 密集库迁移前 | 密集库迁移后 | 十万句库迁移前 | 十万句库迁移后 |
| --- | ---: | ---: | ---: | ---: |
| 形式筛选计数 | 177 | 48 | 27 | 29 |
| 例证页后台返回 | 740 | 502 | 30 | 27 |
| 独立关联全库校验 | 678 | 379 | 1,411 | 27 |
| 新增关联 | 181 | 86 | 231 | 71 |
| 改绑 | 180 | 83 | 106 | 64 |
| 解绑 | 168 | 75 | 223 | 67 |
| 撤销解绑 | 167 | 100 | 331 | 88 |
| 重做解绑 | 161 | 106 | 339 | 87 |

密集库的形式筛选命中 1,000 条。复用已打开的 SQLite 连接测 SQL 本身，计数中位数从 69.2 ms 降到 13.7 ms。查询计划使用 `independent_link_form` 覆盖索引。十万句库的计数和例证页返回为空，校验改善主要来自跳过 50,000 条无关联正文。表中时间到后端返回为止。密集库展开当页 20 条例句仍包含正文、标注和释义渲染。

首次迁移启动密集库约 8.7 秒，其中备份约 2.2 秒、迁移约 3.2 秒。十万句库约 41.1 秒，其中约 25.1 秒用于备份 3.55 GB 数据库，约 8.4 秒用于迁移。测试取自既有隔离材料，正式研究库未打开。安装包沿用上一构建。

## 回归检查

关联回归在正文中放入识别值，确认新增、改绑、解绑、撤销、重做和关联校验均未调用正文 JSON 解码，并核对正文列保持一致。另核对了旧撤销记录、释义继承、同 ID 词条转语素、归并后义项与形式身份、语言包交换及快照备份恢复。

两份源码各通过 740 项前端测试及 816 条样式规则审计。使用既有小项目副本实测中英文 600 × 900 窄窗和 150% 字号，分别提交纯关联修改和正文修改，再撤销两步。同步后窗口实测根字号为 24 px，编辑器内容宽度与容器宽度均为 547 px。
