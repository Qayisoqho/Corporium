## 使用

在侧栏“工作区域与备份设置”中打开“全局设置 → 语言设置”，选择中文或 English，保存后应用。项目选择页也提供语言选择。桌面版把偏好保存在本机 `desktop.json`，跨项目使用；浏览器版使用本机浏览器偏好。

切换前先提交已有的自动保存内容。有未保存的句子、词条或其他编辑时，会要求先保存或取消，保留原草稿。切换通过受控重载应用，恢复工作区、材料选择、主要检索条件、排序、分页和阅读位置；调查提纲、分析查询及已有结果、时间轴窗口与播放头另有状态恢复。

界面语言与研究材料语言相互独立。原文、IPA、翻译、词义、标签定义、语言和书写系统名称、已有提纲、自定义合法性类型及笔记不会自动翻译。例句 UUID、固定号、组内标号、Q/A、合法性符号和引用不变。英文界面新导入的内置调查提纲使用英文默认标题；已有提纲和用户模板保持原文。

界面常用名称包括 Texts、Dictionary、Examples、Elicitation、Timeline、Analysis、Labels & checks。同形中文在不同语境下分别处理：IPA 名称按符号查找；语法参考的 A 是 A argument，Q/A 角色仍保留字母；参考库 TOP 使用已确认的 Topic marker。

## 开发边界

- `web/i18n.js` 提供已登记消息、术语、静态界面以及工作区恢复适配；`web/i18n-messages.json` 是随包的双语目录。原有脚本中的消息 ID 保持稳定，中文原文作为回退。
- HTML 静态翻译仅在应用脚本和语料加载前执行一次。没有扫描动态语料的翻译观察器。属性仅处理可见提示和无障碍说明；选项原值保留。
- `ui_localization.py` 只处理明确的显示契约，如错误、进度、检查说明、搜索字段标题、许可标题。不会递归翻译任意 `name`、`label` 或 `description`。后台任务携带操作类型，以便按对应显示契约处理结果。预览令牌在原始数据上计算，显示时不重算。
- 插入值不经过全文翻译；英文复数在插入用户内容之前决定。JSON／SQLite／语言包及 Word 标准交换字段名不因界面语言改变。
- 新增界面可使用 `CorporiumI18n.ui(中文, English)`，专业术语优先通过稳定术语 ID 取值；避免把用户输入传入通用术语翻译。修改旧消息时同步检查目录中的中英文和插入参数。
- `build/i18n-20261025`仅保存历史清点与一次性转换证据；不要再次执行全源转换或用旧快照覆盖当前源码。后续直接维护当前`web/i18n-messages.json`及现有消息ID，新增文案可用`CorporiumI18n.ui(中文,English)`；任何重新生成目录都须先证明不会丢失后来加入的消息与核订术语。
