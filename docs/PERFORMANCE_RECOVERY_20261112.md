## 材料和计时

复用十万句库、密集关联库、容量审计万句库和最早一轮保留的 2,400 处替换材料。千句库用于单条保存和撤销。使用隔离副本及真实请求、任务、提交和响应编码入口。JSON 版指旧正文仍在 SQLite 的四个 JSON 列中的冻结源码。改动前指 11 月 12 日历史复查时的关系正文源码。一次性准备、索引就绪后的换词、重复请求及完整文件生成分别记录。

十万句库含 50,000 条文本句、50,000 条独立例句、50,000 个词条和 5,000 个语素。密集关联库实测解除 10,000 条文本关联及 1,000 条独立例句关联。各阶段原始样本保存在本地 `build/performance-recovery-20261112`，旧版对照及测试入口在 `build/performance-review-20261112`。

重复统计共用不可变结果，近 30 次运行仍分别保留。已有运行首次加入共用池会复制一份结果，后续只写引用。清除派生统计索引后仍可读结果，便携 JSON 备份为每次运行导出完整载荷，SQLite 项目备份恢复共享结果及其引用。词频下钻只查页内句子的合作者和时间轴关系。组合分析结果摘要一致，文件生成的输出约 0.98 GB。同轮组合分析复测为 JSON 版 80.77 秒、现版 48.62 秒。大文件计时随本机 I/O 波动，现版未复现历史最快的 92.53 秒。

跨文本移动和复制仍在操作前生成可恢复的便携备份。句子备份行直接从 SQLite 生成，保留原 JSON 交换格式。对万句库的 10,100 条文本句和 1,003 条独立例句逐行比较了解码后的完整备份值，并核对操作撤销后的稳定身份和顺序。另一次分段测试旧版复制并撤销为 5.95 秒，低于本轮的 6.31 秒。

## 小项目和仍需区分的等待

千句库每项提交及撤销各重复五次，检查正文恢复。两版都具备有效校验证明的一次复测中，文本译文提交／撤销中位数为 JSON 版 59／52 毫秒、现版 64／58 毫秒。较安静的一轮，备注保存约 46 毫秒、义项定义保存约 43 毫秒，历史记录分别约 41 和 45 毫秒。备注与义项的其他配对结果随测量轮次波动，仍无法确认所有单条写入都达到旧样本。撤销计时包含读取当前撤销代次和提交两次请求。

十万句库完全清空索引后，文本全字段首次准备仍需数分钟。现有记录中的已准备首查与这个阶段口径不同。全字段目录的按需准备和数据回滚仍走同一 SQLite 快照。

在 Edge 中复用千句库，从实际点击计到请求和字体就绪、页面持续约 150 毫秒无相关变化。每种界面语言各一次，使用本轮合并请求后的两份源码配对。表内为秒。

带组独立例句页的媒体状态按当前页合批，请求由 24 个降至 5 个。完整编辑器复用形态选项同一次请求中的词类、书写类型和语义分类，有组分的词条才读取组分关联。受测普通词条打开时的请求由本轮优化前的 6 个降至 3 个，JSON 版为 4 个。以 `small-browser.json` 保留各次请求时间线。

## 复现

本地 `build/performance-recovery-20261112/run.py` 使用 `current`、`before` 或 `legacy` 源码，只允许打开该目录下的隔离数据库。`picker`、`options`、`options-edit`、`reads`、`replacements`、`unlink`、`bulk`、`analysis` 和 `writes` 分组保留原请求。索引、项目副本和历史交换记录由既有材料取得。

9 份隔离库通过 SQLite 快速完整性和外键检查。最终又检查了大目录编辑、密集解除关联及千句保存对照涉及的数据库。两份源码的 816 条界面规则检查通过，改动文件的哈希一致。回归覆盖旧项目切换、新旧备份和语言交换、历史撤销、同形号与目录更新。
