# 句子与关联材料的 SQL 检索

2026-11-01 实施前两个阶段，2026-11-02 接续共享 gloss 与关联材料复用。均已纳入 **2026-11-02 的0.9.01101同号重建**，与附加层内部行距、MPW一起交付；原阶段报告中的“仅源码”保留当时语义。

## 使用范围

文本、统一例句检索及独立例句组中，IPA、自由翻译、备注、词形、语素形式、gloss、全部字段、附加层与书写形式由数据库匹配、计数和分页。包含、完全相同、开头、结尾及大小写设置保留原规则；只展开当前页完整句子。统一例句的 original 字段也可索引。

词典／语素检索将关联例证的命中例句身份映射到当前关联条目，同一例句不再为每个关联条目重复展开。词典字段目录也可复用；相关条目、类、层、书写类型或语法定义改变后自动失效。调查检索使用同一附加层／书写形式搜索投影。

首次使用相应字段时准备派生键，保存后可在重启时复用。超过 200 项待准备时显示双语进度，并可取消；后台词典检索也允许取消。未完成的本次准备回滚，不修改研究材料或新增业务撤销记录。日常少量变化在查询前局部更新。

结构警告筛选仍使用原有分析路径；不增加跨词格字符串搜索。已准备的投影可在只读连接复用；需要更新但连接只读、写锁冲突或快照已固定时回退原读取器。没有新投影的旧数据库也保留原路径，准备检查不会预占写锁。

## 各入口的匹配边界

这些索引共享结果，但不混用不同字段的含义：

- 词形沿用 corpus.clean，排除纯音系边界；语素形式沿用现有单词分析。
- gloss 沿用原有成分拆分和上下标内容提取，排除纯边界词格。
- 句子“全部字段”沿用整词 plain(form)／plain(gloss)，纯边界词格仍按原有规则参与；不是把所有 gloss 拆分键简单并入。
- 词典例证沿用可见叶值与字段路径、枚举显示名称、语法标签和名称引用，保留自己的精确匹配边界。
- 文本“备注”包括句子备注、语言备注和所属文本备注；统一例句保留原来的备注范围，“全部字段”另外保留其 original 范围。
- 自定义层按句子实际语言、层的锚点和有效单元判断；孤立旧单元不参与。默认检索只用可搜索层，明确指定时仍能查询不可搜索层。词典调用层同时匹配中文和英文派生值，定位保持原有显示值。
- 关联书写形式只通过当前关联进入例句搜索，保留原有独立例句引用核对规则。词典搜索没有因此扩展到原来范围之外的无关条目。

规范键保存 NFC 原大小写、Python casefold 和反向键。精确／前后缀使用 B-tree；不少于三个 Unicode 字符的包含查询用 FTS5 trigram 候选加 SQL instr 字面核对。短查询、NUL 或不支持 trigram 时回退 SQLite 去重键扫描，不把短查询当作无结果。

## 共享有效词格

gloss_search_index.py 保存组合、意义依赖、有效词格、规范键和出现位置。组合身份由源词格结构、有效意义身份、绑定模式、覆盖、附加模式与来源版本确定，排除稳定出现位置身份。不会仅因为两个显示字符串相同而合并研究身份。

同一输入组合只求值一次，各出现位置引用它；释义规范值继续去重。有效词格复用 gloss_inheritance.render_word，保留整词／子成分优先级、空覆盖、冻结、环缀与失效绑定规则。内容指纹作为输出版本，避免已释放 SQLite 行号再次使用时误用缓存。

源句子或绑定变化时只重建相应来源的组合引用；义项变化只标记依赖组合。查询前重新求值，输出未变则跳过搜索键更新。不会逐词格复制有效释义，也不回写句子 JSON 或 corpus_units.gloss。前两个阶段的语素形式投影仍有自己的待更新队列。

## 关联材料复用

material_search_index.py 将例证拆成句级内容和共享有效词格，分别保存字段键。每次查询先得到命中例句身份并去重，再连接当前词典关联；关联新增／移除直接影响结果，不依赖旧的条目命中缓存。

文档跟踪实际使用过的词典名称、语法标签、书写类型和发言人标识；名称改变只重建依赖文档。不同语言和词典／语素上下文分别管理，避免名称空间污染。每个检索对象拥有独立临时身份表。

自定义层及书写形式按来源增量准备；词典目标的书写或相关属性改变时更新实际依赖的来源。手动单元和 corpus 书写投影不因无关改义重新展开。所有关联材料共享 search_keys.py 的字面键与 Unicode 匹配规则。旧内存例证索引保留为回退路径。

## 更新、取消、备份与空间

受信触发器覆盖来源、单位、绑定、意义、关联、定义和名称变化，包括撤销／重做与外部 SQL。触发器显式检查待更新队列，避免 SQLite 外层 UPSERT 改变 OR IGNORE 的行为。按来源清理和反向依赖都建立索引。

更新与查询处于同一数据库事务／快照；大批准备及后台词典任务绑定实际项目路径，沿用内存保护、SQL 中断和最终提交前取消。初始准备、日常修改后的更新和后续查询应分别计量。

派生表不进入业务 JSON、单语言交换和撤销历史。SQLite 便携备份移除 sentence_search_*、gloss_search_*、material_search_*、projection_search_* 的表／FTS 和本模块触发器。恢复由可信源码重建，继续拒绝外来触发器和视图。

刷新时使用有界规范值、输入与书写缓存，删除不再被引用的组合、文档和搜索键。数据库仍需额外磁盘空间；空间取决于不同组合、例证叶值和自定义内容数量，不能直接套用前轮原型的附属表大小。

## 验证与实测

tests/test_shared_search_index.py 将完整响应与旧路径对照，并检查同组合只刷新一次、不重写出现位置、复杂继承／冻结／环缀、Unicode、不同字段边界、修改／撤销、只读连接、字段目录复用及后台取消。前两个阶段、附加层、词典搜索、调查和备份测试继续覆盖各自范围；旧内存缓存的淘汰测试明确运行回退路径。

两份源码各1,249个不同后端用例最终通过（全量初跑＋定点复验，按当前名称去重）；最终检索相关158项分别通过，各577项前端通过，无跳过。初跑中的Windows长临时路径与本机回环连接限制已分别复验。

性能复用既有万句密集继承和五万句测试源库的隔离一致副本，只在副本添加合成附加层和书写标记；不打开正式数据库，不复制媒体。完整响应编码／哈希与查询一起计时。最终查询计时在准备完成后进行，只衡量后续查询；报告单独说明已有投影检查与尚缺例证投影的准备记录，不能把快速检查时间当成首次建索引成本。未清空操作系统缓存，也不把后端耗时当作网页端到端延迟。
