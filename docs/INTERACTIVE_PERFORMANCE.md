## 已实施的算法

- **句子检索**。SQLite 把稳定的句子身份按 256 个分块。每个规范值、字段、词格位置保存一个标出命中句子的位集合。跨值或字段匹配时合并位集合，保留精确的句数和去重词格数，只展开当前页位置和正文。罕见命中把具体 ID 直接传入文本句和独立句两条查询分支，可避免 SQLite 为一两个 ID 临时整理整个语料库。源数据和派生词格变动时标记受影响块，准备工作与发布在同一事务内完成。旧库、不可写快照与索引准备冲突可使用先前的读取器。
- **独立例句库**。按有效组成员、最早例句编号和散句身份在 SQLite 中筛选排序。匹配组名或语境可以展示上下文，句数按实际命中成员去重。按项目数据版本短时复用排序后的窄身份和组内命中，按页展开正文。超过缓存上限时直接按 SQL 页取数，页外大组成员不会全部装入结果缓存。
- **语法标签**。定义单独分页和筛选。用量索引把有效词格分析与各语言、来源的出现次数联系起来，源句改动只调整相应计数。分类复用原有识别器，保留显式标签、别名、上下标和大小写条件。改说明可沿用原识别结论，改写法时对不同标签组合按出现次数重新分类。正式改名继续真实更新源材料，事务中复用重复标注串的解析，一次连接释义绑定与其所属语言。手动完整检查仍可核对结构性问题。
- **同音语素表**。保存稳定组分、共享身份、显式和暂代读音的可重建索引。更动源词、语素或活跃组分关联时更新受影响来源。先按读音或韵母定页再装载详情，用同一版声韵调清单复用韵母别名和签名。结构视图只传显示所需字段。切换或确认时可按资料版本复用已显示的语素内容，重新取得分类与页数。人工确认仍是正式项目数据。查来源词也能通过实际组分身份定位。
- **编辑与词典**。已有文本句只改译文或备注时保留原生词格，服务器核实实际前后记录，客户端核对回执、视图及项目版本再替换句卡。筛选、警告或结构可能变化时重新查询。既有义项只改文字时可由完整校验基线和不变的身份范围作局部验证，再读取当前词条及其受影响的例证。非空选词和词典全部内容使用可更新的可见词叶索引及例证归属关系。删除、撤销、外部写入、语义依赖变化仍参与校验与缓存失效。
- **统计、分析与批量操作**。小范围统计先取相关句子身份。组合分析按实际引用读取词典正文，已保存分析翻页可复用排序下标和分布。首页复用去重的候选身份，每次仍从完整候选中随机取样。批量解除和义项影响预览通过词条例证归属定位独立句，保留原有冻结、冲突及撤销处理。

## 准备成本和剩余等待

词典的名称／类别依赖跟踪现在按键读取。对真实的 155,018 项名称目录和相同的 400 份例证文档，旧实现用 1,847 ms，新实现用 16 ms，字段值、字段目录和依赖摘要完全相同。在同一上限库清除指定完整词典上下文的派生文档及其本地检索键、保留共享字面值池后，重建并返回首次正确结果共 **76.25 s**。重建前后的完整结果摘要相同。

用 SQLite 页面统计汇总，记录在验收清单中的具名新增派生表及索引占 277.5 MiB。共享字面值池、自动索引和空闲页另计。这里给出所列结构的占用，净增量会随资料分布和已准备的搜索上下文而变化。

十万句仍有明显超过目标的操作，尤其是新输入的高命中条件、多个大例句组的首屏、义项保存后的详情与例证绘制，以及整页稳定。大库首次准备、全库主动检查、涉及万处引用的改写和全量输出需要单列完成时间。

万句密集库复测中，选定文本统计中位数由 175 降到 88 ms，选定文本的组合分析由 944 降到 560 ms。整种语言统计约 6.11 → 6.07 s。三种结果的完整内容摘要都一致。全库统计仍须建立逐词命中和词汇分布。此轮没有在上限库为全库改名、批量解除，以及所有统计组合取得 P95，相关改动的验收以正确性回归和已实测的样本为限。

## 三处等待的补充分段诊断

2026-11-10追加。复用同一十万句隔离库、万句密集库和原有小型关联材料。本节交付诊断和隔离原型，产品运行文件的改进进入后续实施。原表的整语言统计 6.07 s 只覆盖万句密集库的 `corpus_statistics.calculate`，完整统计入口还要保存分析快照及读取结果页。此次补测覆盖这些步骤。

普通计时与剖析分别记录。剖析会增加开销，主要用于定位调用关系。原型均在本机诊断进程中替换函数、使用临时表，采用同一输入逐项对照完整结果，不构成产品功能的验收。本节的小样本不作 P95 结论。

### 高频词形的首次检索

十万句中查询 `ger`，清空命中、范围及句卡缓存后，普通一次为 1,310 ms，同进程重复为 11、8 ms。另一次剖析共 1,347 ms，其中 `scoped_page` 为 1,116 ms，匹配位集合为 155 ms。查询计划显示两条句子分支全量遍历，再连接稳定身份并建立临时排序树。其工作量仍随整个范围大小增长。

仅删除内层 SELECT 中未用的正文列，四组对照没有稳定改善。把当前语言的两类句子身份、稳定序号、文本及顺序字段存成窄目录，并给顺序建立覆盖索引后，首页和第 500 页的四组结果均完整一致。

| 条件 | 当前实现 | 窄目录原型 |
| --- | ---: | ---: |
| 首页，两次 | 1,174、1,189 ms | 437、423 ms |
| 第 500 页，两次 | 1,233、1,209 ms | 438、438 ms |

这份固定范围目录准备一次用了 744 ms，共十万行。每个计时样本都清空命中、范围和句卡缓存，系统文件缓存保留。原型直接针对当前语言的混合来源，尚须接入文本选择、语码和句子语言筛选等条件。产品方案是在源记录变动的同一事务内维护窄身份目录和排序键，结合现有分块位集合统计准确数量，再取得当前页。语言、文本顺序和成员身份改变时只更新相应记录。

初期一次试验发生在保存与撤销之后，派生索引尚未准备，读取进入原有扫描回退。该次排除在表中。用正常可写检索入口完成派生更新后重测，并断言每次实际进入位集合与范围目录路径。

### 保存后的详情和例句刷新

在一次带剖析的真实界面操作中，既有义项保存从点击到稳定用了 1,412 ms，后台写入、校验及提交任务为 57 ms，其中提交约 4 ms。随后 `showLexeme` 重读详情并发出九个请求，形态选项要遍历 55,000 个词典目标的关系字段。该 SQL 用了 317 ms。后续标签等轻请求累计等待桌面项目锁约 497–520 ms。删除资格检查又对五万独立例句做 `json_each`，约 172 ms。请求时间重叠，不能逐项相加。此次浏览器脚本、样式重算及布局分别约 132、106、18 ms，稳定口径另外含连续 150 ms 无页面变化。

隔离原型将反向派生关系和组分引用预先归一为身份边，独立例句引用数使用已有的 `evidence_owner_pairs`。两项后端读取四次由 445–476 ms 降为 38–45 ms，完整返回相同。关系目录准备为 382 ms，独立例句派生脏项准备为 29 ms。上限材料缺少这类词典反向关系，另用既有小库核对 42 个目标，并复用已有的正向、反向关系测试核对四条非空关系。

独立例句只改译文还会触发全组校验，遍历 1,000 个组和 8,072 条成员关系。轻量分段计时中该步骤约 43–46 ms。正常保存三次为 87–100 ms，临时省去该步骤的对照为 41–49 ms，六次均经正常撤销核对原生正文及身份，组和成员表在改译文期间完全一致。这个对照只用于测量可节省的上限，正式局部校验仍须根据实际变动和有效完整校验基线证明组结构与语言未变。

后续实现先复用既有义项文字编辑回执，更新当前义项和实际受影响的例证，保留其他详情及其编辑事件。反向关系查询接入可增量更新的目录，删除资格读取已准备的引用索引。翻译及备注保存按实际变动缩小组校验，并测量重新可编辑的时间。只读请求的项目锁范围需要结合固定项目身份与数据库快照处理，项目切换和写入一致性继续参与验证。

### 全语言统计的计算与结果读取

万句密集库一次普通底层计算为 4.5–5.3 s。剖析样本共 11.58 s，约 1,623,000 次递归 `deepcopy` 调用累计 5.39 s，另有密集关联去重 SQL 约 1.7–1.8 s。引用去重建立临时分组，再读取对应句子。独立例句有结构引用时，还会深复制全句及引用快照，重新分析整句。

在同一密集库交替做三组完整结果摘要核对，预存已验证的引用身份后约 1.96–2.09 s。再将局部新解析正文的深复制改为保持完整 JSON 副本的复制，普通底层计算中位数由 3.83 s 降至 1.71 s。引用身份投影一次准备约 1.82 s。更早直接使用独占局部输入的对照约 1.42 s，保留副本的版本用于评估可落地的方向。产品实现应按实际结构引用只准备所需词格，保持引用快照及原生正文的所有权。

`analysis_payload.Reader.value` 遇到跨块的值时，每补 64 KB 都重新从该值开头调用 JSON 解码器。词频大字段反复解码，工作量随字段大小加速增长。一次单独剖析约 27.71 s，调用 `raw_decode` 921,643 次，其中 1,626 次构造 JSON 解码错误。成倍扩充未完成值的缓冲区，保持原有流式校验、Unicode、数值边界及取消处理后，三次普通首读为 3,404、3,878、4,165 ms，完整元数据摘要一致，既有十项读取契约通过。

仅保存概览所需的统计和词频汇总头部，样本为 27,458 字节，20 次单独解码约 0.32–0.56 ms。这个数字只衡量预先形成的汇总解码。生成和维护汇总、数据库读取与界面绘制仍需在接入后计时。

当前相同数据及查询已有快照缓存，任何有实际变化的保存及撤销都会使全项目分析版本失效，启动初始化也会重设版本。后续应为统计建立按实际依赖更新的版本与逐句事实，分别维护计词、语素、词形、合法性及有效引用的汇总。同一句被多个词条引用仍要去重，大小写、附着成分、跨语言及自定义条目统计继续按原定义处理。首页概要、词频页和例证页分开按页读取，历史快照与导出保留可复核的完整结果。读取器改进和摘要分存适合先交付，增量统计随后接入保存、撤销、导入和外部修改的失效判断。

本节证据位于 `build/interactive-performance-20261110/wait-diagnosis/`，包括 `search.json`、`catalogue-experiment-summary.json`、`detail-experiment-summary.json`、`inline-phases.json`、`statsjson-experiment-summary.json`、`counts-entry-upper.json`、`counts-payload.json` 和 `additional-contracts.json`。真实浏览器四项保存均通过原入口撤销复核，另六次轻量保存／撤销也核对正文与身份。单项运行测试与隔离原型的结果均独立记录。

### 统计结果按页读，失效判断按实际依赖更新

修正大字段跨块解码的重复工作。新统计运行保留完整、可独立复核的结果，同时将概览、词频项目、逐词位置和分块命中分开存入可重建的SQLite派生表。概览不读整份大快照，词频页只取100项，下钻只取30个位置及对应命中块。逐词位置与项目摘要分表，避免读取小摘要时遍历大位置字段的溢出页。

临时计词结果的固定五字段命中可无损按句归组，采用较快的压缩级别。公开读取仍展开为原有结构。旧格式、有扩展字段的命中及完整固定快照继续兼容，导出保持完整内容。本节优化完成时内部分析引擎版本为17；11-15的释义标签修复已升级为18（见[后续修复](UI_REPAIRS_20261115.md)）。临时计词编码统一由`analysis_payload`展开。大批量派生写入在原预算不足时临时提高到32MiB页面缓存，结束或异常后恢复连接原设置。实测原默认约2MiB缓存造成反复读写页面，是早期试跑中索引构建异常变慢的原因之一。

### 范围身份目录与义项局部刷新

句子范围使用可更新的窄目录，保留文本顺序、来源、语言、合法性及稳定序号。检索直接复用目录中的序号，免去逐句重新连接身份表。范围脏项与原生记录的保存、撤销和外部SQL修改处于同一事务，无法写入派生结构时保留原读取路径。

查询`ger`，每次清空命中、范围和句卡缓存，新旧完整响应摘要一致，各预热一次后正式50次。旧实现P50／P95为1,207／1,288ms，本轮为624／668ms，当前进程首次分别为1,179／614ms。每次断言实际进入索引路径，避免把扫描回退混入对照。

词典反向关系按身份边增量维护，删除资格复用独立例句归属索引。既有义项文字保存核对提交回执、视图与项目修订号后，只更新对应义项及当前页例证，保留详情的编辑、复制和删除按钮。真实界面曾发现媒体面板会再包一层容器，已修正义项定位，并增加按钮身份保留断言。独立例证改为数据库分页，保留书写形式过滤、跳页、跨页定位、当前页批量选择和正确编辑对象。

独立例句译文保存先验证组结构校验基线。结构与语言未变时复用该证明；组、成员或相关语言的修改，以及会使旧缺失成员重新出现的插入，都会使证明失效，继续执行完整校验。

### 准备成本、验证及剩余瓶颈

清空后重建十万句统计事实约38.94秒，另有约628ms初始化。此成本与上表已准备后的运行分开，首次使用仍可能等待较久。单次只改一个计词形式的事务试验，只有1句标脏，更新该句事实约120ms；随后全库汇总仍需4.09秒。回滚后正文、事实和失效版本恢复，完整结果可再次复用。该试验只改变隔离库事务内的既有记录，不产生新压力材料。

剩余主要成本为首次派生准备、真正改变计词结构后的全库汇总与完整结果保存、下钻当前页的例句展开，以及首次高命中检索的范围合并和句卡读取。本轮尚未把这些操作全部压到100ms以内。后续应分别评估可更新的总量与词频汇总，以及当前页例句的批量展开，再确定是否值得增加索引和维护成本。

当前隔离库本轮具名派生表及其索引共约260.3MiB，其中5份统计分页缓存约171.6MiB。体积随缓存数量、引用和词形分布变化，原生正文、完整快照及空闲页另计。派生目录可重建，备份恢复清理覆盖这些表及其触发器，避免遗漏新索引的写入依赖。
