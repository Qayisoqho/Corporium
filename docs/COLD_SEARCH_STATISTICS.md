# Corporium 首次词典搜索与统计优化

日期：2026-11-01。源码版本 **0.9.01030**。复用现有测试工作库；没有生成新的大容量语料，不修改功能、检索范围、统计口径、关联规则、备份或撤销规则。本轮不重建安装包。

## 结论与原因

主要瓶颈是**查询执行顺序、读取无关关联，以及反复解析和构造对象**。当前证据没有显示容量已经到顶，也不支持直接换数据库或重建所有数据结构。

- 统计的引用查询原先先扫描131万个词／语素单元，再逐个找关联；已有索引并未阻止规划器选择这条较贵的路径。现在从词条及实际关联出发，按身份查单位，先去重句子／语言，再读取句子JSON。诊断轮该引用阶段约22.39→4.69秒；这是单次阶段计时，不混作整轮提速比。
- 普通词频原先会为每批句子读取全部词格关联，即使库中没有任何能计入语素统计的语素／组分关联。现在先证明这一情况；自定义统计或存在相关关联时继续完整读取。当前五万句样本的这项旧读取约28秒，判空后不再重复执行。
- 重复词形原先每出现一次也会构造默认统计行并编码其键；纯整句引用会进行不影响结果的形态解析。现在按不同词形创建行，结构引用使用已有的有界词形分析复用。
- 词典默认搜索仍包括原有的关联例句。首次扫描不再为确定不可能命中的文本例句构建完整字段文档；候选仍执行原匹配。登记标签别名、引用名称、Unicode规范化、大小写和译名都保留。宽泛查询达到采样条件后，当前可见形式／标注明确命中即可确认该例句的同一次命中。独立例句保持原有文档缓存路径。

## 数据、计时与等价性

使用原有50,000条文本句＋5,000条独立句、131万个单位、15万条显式关联及15万条继承绑定的工作库；另用既有千句库、万句库，以及119,934条显式关联／130,934条继承绑定的万句密集库。没有新造大库。普通五万句样本有605,000词次、14种不同词形，重复度较高；加速倍数取决于数据分布。其有效语素词次为0，因此“没有相关语素关联时跳过读取”的收益不能外推到所有项目；有根／词缀／组分关联的完整路径另有回归测试，自定义统计仍读取完整关联。

本机Windows 11、Python3.12.14／SQLite3.53.1。直接调用实际词典读取和 analysis_workspace.run；每次新连接、清空证据缓存，统计明确确认 cached=False。统计在同一工作库事务内暂时移除旧运行缓存，实际计算、压缩并写入新结果，随后回滚；缓存移除和最后回滚不计时，不包含最终提交、项目升级、浏览器布局或媒体播放。未清空操作系统磁盘缓存。普通结果重复三次；补充条件通常各一次。不可将这些后台核心计时当成点击到整页完成时间。

各组词典完整响应哈希一致；统计对**完整解压后的结果内容**逐字节校验，包括命中顺序、位置、词形表和统计值，全部一致。统计仅改变读取和计算工作量，保存格式及结果口径保持不变。首次结果仍要扫描范围并编码保存；本轮没有将计算挪到启动或后台预热来隐藏等待。

## 防止退化与边界

词典快速排除只作用于简单的全部字段文本例句搜索；复杂条件和独立句继续原路径。原始JSON仅在字符串无转义、没有待组合的词典标注、继承标注未变化，且搜索词不可能命中数值写法时复用，否则编码当前有效投影。含引号、反斜线、控制字符、译名等不能由原文字面安全证明的情况回退完整检查；登记名称通过真实引用编号检查。命中或排除的证明只属于本次查询，不发布成供其他词复用的空文档。

新增整组词格字段复用限4 MiB，仅在一次操作内使用，低复用时停用；宽泛搜索也会停用无收益的排除步骤。现有16 MiB证据结果缓存和16 MiB统计元数据缓存规则不变。修改、外部SQL、旧WAL快照、取消、撤销／重做和语言隔离继续验证。

覆盖索引试验在既有万句库中反而变慢，未采纳；试验索引已回滚，源码没有增加索引、业务表或数据迁移。当前全库词典首次搜索仍需等待，特别是需要完整展开的结构条件；把它进一步压到数秒，值得单独评估可增量维护的检索投影，并验证义项、标签、类、书写和外部改动后的同步失效成本。
