## 语法标签与同音语素表的首次准备

语法标签定义和保存说明走小范围读取或更新。十万句库首次准备使用次数和候选时，剖析在 65 秒时主动取消任务，尚未完成。已记录的约 65 秒都在 `grammar_usage.prepare` 生成用量数据。

密集库的同一准备完整运行约 22.90 秒，完成后再次读取用量和候选为 25 毫秒。同一密集库将一条独立例句关联改绑、将一个词条组分改绑到现有语素，单次保存分别为 67 和 50 毫秒，均核对了撤销后的关联。

同音语素表首次走界面的后台任务入口时约 21.58 秒，其中旧的逐项扫描约 21.47 秒。这个入口用只读连接，不能持久化待处理的同音索引，于是回退扫描。另用允许提交派生索引的普通请求完成准备约 15.96 秒，其中 `homophone_index.prepare` 约 15.43 秒。这两项是单次剖析计时。

索引写入后，新进程中同音语素表连续两次响应为 235 和 64 毫秒。

文本替换的 `text_replace.records` 通过兼容视图逐条组装正文，解析后合并有效释义，再把整句编码为 JSON 供匹配和签名使用。即使只查译文，`text_replace.plan` 也读取整范围的词格单位及词典关联生成校验摘要。提交重新执行同一计划。独立例句分支的摘要只读取相关标注和关联目标，因此同样 50,000 句的范围等待明显不同。

词典替换的 `dictionary_replace.plan` 在限定字段和命中身份之前展开当前语言的全部词典正文，并将这批正文用于预览签名。预览在回滚用的保存点中验证试写，提交会再次生成计划并执行校验。先按 SQLite 标量或已有索引筛出候选、再只展开候选正文，可以直接缩小这两个流程的读取范围。提交仍需要校验预览时确认的字段、版本和相关引用。

## 计时归因

- **词条备注。** 单独剖析的一次保存共 21.39 秒，`lexicon.validate_changes` 占 21.30 秒。此次正文只有备注改变，同时产生了一项派生释义记录变化，文字修改的快捷校验未命中。传入 `validate_links` 的受影响身份只有一个词条，函数仍为全部 55,000 个词条及语素准备定义，其中 `dictionary_rows.raw_bodies` 占 13.52 秒，Python 的 JSON 解码合计约 95 毫秒。
- **文本查找替换。** 10,000 条文本句的密集库剖析一次全语言预览，共 28.57 秒。读回并重组所有正文占 16.00 秒，校验摘要中的词格与词典关联两组 SQL 执行和取数约 7.56 秒。整次操作中 Python 的 JSON 编码约 4.98 秒、解码约 3.67 秒，部分时间已计入前述阶段。50,000 条文本句的 85.87 秒是另一次无剖析计时。
- **词典查找替换。** 密集库单次预览 17.38 秒，其中生成计划 5.13 秒、试写和校验 8.88 秒、计算冲突 3.22 秒。试写内 `validate_links` 占 8.80 秒。提交还会正式写入并校验。
- **首页和统计。** 密集库首次首页 1.37 秒，其中构建候选目录占 1.27 秒。密集库首次整语言统计约 24.43 秒，`statistics_facts.prepare` 占 22.87 秒，读取正文、词格和词典关系后建立统计事实。十万句库首次整语言统计另测得 111.70 秒。
- **文本目录与独立例句库首页。** 单独剖析时，文本目录约 391 毫秒，按文本计算句数的 SQL 约 368 毫秒。独立例句首页约 361 毫秒，计数约 130 毫秒，排序和选取当前页约 153 毫秒，渲染所需的 20 条例句增强约 25 毫秒。对默认范围直接查询所有者和顺序，再按页读取正文，可减少首页查询的工作量。

## 按命中范围执行的复测

复用同一十万句合成库的两份独立副本，两者都使用删列后的 SQLite 正文结构。以下每个操作各测一次，包含任务提交与响应。应用后检查实际写入，撤销后逐项比较受影响的正文。耗时受首次磁盘读取和索引准备影响。

| 单处替换 | 预览，改动前 → 改动后 | 提交，改动前 → 改动后 |
| --- | ---: | ---: |
| 50,000 条文本句的译文 | 116.50 → 0.35 s | 67.02 → 1.90 s |
| 50,000 条独立例句的译文 | 12.83 → 0.47 s | 10.39 → 0.63 s |
| 50,000 个词条的基本词形 | 56.91 → 2.48 s | 66.25 → 0.79 s |

文本和独立例句的译文、音标直接在 `sentence_text_rows` 筛选。包含匹配仍可能在 SQLite 扫描该字段。预览读取匹配句的正文以验证 Typst 往返，提交只组装选中的句子。提交前在写入事务中重查实际命中，并复核原值、修订、位置与相关标注和关联。自动测试核对了新增命中导致预览失效，以及未命中记录被编辑后仍能提交。原词格、词典关联和未选记录通过原来的事务和撤销机制保留。

词典当前条目和已确定的搜索结果先按身份限定。全语言只替换基本词形或语素形式时，先查相应的标量列。组分引用使用关系行或已准备的反向索引。词典提交在正式写入后校验，预览在保存点试写并回滚。没有可靠的局部校验证明时执行既有全量检查。

上限库中，两次单个词条备注保存约 305、329 毫秒，撤销约 597、611 毫秒。这两次含函数剖析。单个调查提纲标题、调查笔记标题保存分别约 274、287 毫秒。密集库的同音语素表首次后台准备并返回约 3.24 秒，随后再次调用约 49 毫秒。核对两次结果一致，待更新队列在首次提交后清空。

本机 `build/telira-workflows-20261112/` 保留测试入口 `workflows.py`、逐次样本、浏览器请求时间线和函数剖析。复跑时将 `build/relational-cutover-20261112/` 下的 `upper.sqlite3` 和 `dense.sqlite3` 复制到本轮目录，再按操作分组运行测试。原有合成库仍供复用。安装包沿用上一次构建。

词格替换、全字段检索及标签用量的前后样本和函数剖析在本机 `build/search-range-20261112/`。入口为 `compare.py`，分别运行 `replace`、`dictionary`、`morpheme` 和 `grammar`。每组首次计时前从原材料复制对应数据库。对照版用 `--before` 读取同目录下的基线源码。

单条替换的分段计时和浏览器请求记录在本机 `build/replace-interaction-20261113/`。`browser.cjs` 复用 `build/performance-recovery-20261112/` 内的测试副本，实际写入后逐步撤销并核对原值。`before/` 保留对照源码，最终复测文件名带 `delivery`。

首次预览及自动关联的计时在本机 `build/preview-auto-20261113/`。`bench.py` 的 `replace`、`auto` 和 `whole` 组复用同一批现有测试副本，`browser.cjs` 用隔离项目验证界面。后端与浏览器改后复测文件名带 `verified`，同环境浏览器对照文件带 `same-browser`，整语言预览缓存复测带 `retained`。安装包沿用已有构建。

界面稳定和整语言的分段记录在本机 `build/preview-latency-20261113/`。`before/` 保存本轮改动前的源码，`whole.py` 对现有测试库执行预览、提交、核对候选及撤销，`browser.cjs` 记录 Edge 的请求、布局、绘制和稳定时间。整语言交付记录带 `delivery`，最终浏览器记录带 `confirmed`。

独立例句词格删列的本机记录位于 `build/independent-word-source-20261113/`。最终性能对照文件名带 `serial`，`migration-*.json` 保存校验摘要、快照时间及迁移时间。
