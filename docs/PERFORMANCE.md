## 能力范围与结论

现有 562 个测试数据库合计约 26.95 GiB，另有约 4.79 GiB 媒体。总量由多个库及历史副本组成。本轮单库覆盖至 **50,000 条文本句、5,000 条独立例句、1,310,000 个词／语素单元、150,000 条显式关联、150,000 条继承绑定、150,000 个附加标注格及 50,000 个时间区间**，另有 5,000 个词条、5,000 个语素条目及 100 个文本。升级后的该工作库约 1.1 GiB。

另使用 10,000 句密集继承库，含 119,934 条显式关联和 130,934 条继承绑定；普通万句工作库因既往测试已有 10,100 句、1,003 条独立例句，本轮按实际数量记录。没有调用造库器，没有生成新的大容量语料库。导入、复制和导出均复用现有句子。

日常分页与时间轴局部读取可用；全库首次扫描、批量修改及大导出仍明显依赖数据量。当前材料未覆盖单个 27 GiB 项目、数百万独有词形、多人长期并发写入或多小时持续运行，不能据此给出崩溃上限或所有操作即时完成的承诺。

## 保留的实现改动

1. IPA、译文和备注搜索只扫描所需字段；匹配列表保留身份与命中位置，再从同一数据库快照读取当前页完整例句，避免暂存所有整句 JSON。
2. 词典信息附加层搜索复用本次查询的纯词形分析，并跳过没有关联、不会产生实际字段值的位置；正常例句显示仍保留所有占位。继承标注的独立句搜索使用完整关联引用，补齐旧路径漏项；旧源码已重现此漏项。
3. 词典／语素的完整关联例句搜索，复用经独立数据库观察者证明有效的完整结果。文件状态、数据版本、语言、查询和词典目录均参与校验；外部 SQL、事务内写入、旧 WAL 读取或项目更换不能混用结果。新增缓存上限 16 MiB，保存为不可变字节；超出预算回退原计算。
4. 词频页复用已验证、不可变的统计元数据，新增缓存上限 16 MiB。普通词频表不保留全部命中对象；点开词形时只保留所需命中及例句，在该份内容已完整验证后可提前结束读取。旧数据格式、冻结快照、索引顺序与重复项、取消、失效判定和本句关联规则保持原样。

未改变业务数据格式或统计口径；没有关闭自动备份、结构验证、数据保护或撤销。批量标签改名的试验未形成一致收益，相关运行代码未纳入交付；其试验计时不作为优化成绩。

## 并发、取消与连续调用

后台统计取消后的事务与记录数核对通过，取消响应约 0.017 秒。分析期间10次分页读取范围为 0.119–0.150 秒；同时修改按原规则返回 HTTP 409，任务完成后重新保存及撤销正常。没有解除这项保护。

任务结束后的100次混合读取，回收后的工作集为 58.5–59.9 MiB。另用真实后台发送路径丢弃响应字节、配合分配追踪运行320次，工作集为 37.3–38.3 MiB，追踪到的 Python 常驻增量约 41.0 KiB，没有持续增长趋势。这是短循环验证，不是多小时泄漏保证。早期负载脚本因未预期409而提前退出，后续读取与尚未结束的统计重叠，其内存增长不作为泄漏证据。

## 复现与边界

使用 Windows 11 本机（16个逻辑处理器）、Python3.12.14／SQLite3.53.1 的源码处理路径。普通API基准在同一进程通过真正 Handler 生成响应，并由驱动接收和解析JSON；计时及进程工作集包含这部分开销。连续内存专项单独采用丢弃响应字节的口径。写入使用原有事务、验证、自动备份及撤销。每种数据规模独立进程，常规读取三次，缓存第一次／后续明确拆分；大型写入和导出通常单次。第一次指进程／应用缓存，未清空操作系统磁盘缓存。采样工作集是50毫秒间隔的观测值，不是系统内存总量或绝对峰值。

普通万句与五万句为旧测试工作副本；首轮已独立记录兼容升级，后续请求不把升级混入普通读取。五万句旧格式第一次升级652.83秒，随后正常启动约7.64秒，两者是不同工作，不能作为提速比。测试期间为保护历史证据，未让备份保留策略删除旧轮次文件；正式运行的保留策略没有修改。

材料词形重复度较高，多个模块的缓存收益不能外推至完全不同分布。不同日期的历史报告不参与本轮提速计算。全字段首次扫描、全库统计计算、全库标签改名与大导出仍是主要等待点；数据库总占用、单库句数、单元数、关联密度和媒体体积应分别判断。

详细原始证据位于开发目录 build/capacity-audit-20261101；大容量测试数据和工作文件不随公开源码分发。
